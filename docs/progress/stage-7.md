## 판단 (계획과 다르거나 계획이 정하지 않은 것)

- 단원 판정은 평가 블록 답만 쓴다. 연습 문항은 판정에 넣지 않는다.
- 판정 순서: 통과 → 혼동(같은 오개념 3회) → 보충 → 기초 확인. 같은 실수 4번으로 50%면 기초 확인이 아니라 비교 블록으로 간다.
- 보충 문항은 틀린 문항의 동형 그룹에서 채운다(최대 4개).
- 역할 태깅은 문장마다 틀린 표시 2회까지 통과로 본다.
- 기초 확인에 실패하면 순서상 앞 단원으로 안내한다(선수 skill 그래프가 아니라 단원 순서).
- 아직 만들지 않은 문장 과제 종류(끊어 읽기 등)는 "준비 중"으로 표시하고 넘어가게 했다.
- 개념 복습에서 푼 문항은 저장하지 않는다. 그래서 다음 복습 때 같은 문항이 다시 나올 수 있다. 저장하려면 진도 스키마에 필드를 하나 더 넣어야 해서(승인 필요) 남겼다.

## 테스트

- 단위: `npm run test:coverage` 290개 통과, 라인 커버리지 98.19%(lib/engine 97.33%, lib/content 97.36%, lib/repositories 91.17%).
- e2e: `npm run test:e2e` 26개 통과(모바일·데스크톱).
  - 데모 단원 전체: 개념 → 역할 태깅(탭, 한 번 틀려 흔들림 안내, 둘째 문장은 키보드) → 문장 조립(되돌리기 포함) → 연습 오답 → 힌트 1·2 → 제출 전 해설·오개념 문구가 DOM에 없음 → 해설 → "비슷한 문제 풀기" → 정답 → 평가 8문항 중 7개 → "통과했습니다" → 대시보드에 다음 단원.
  - 평가 중 새로고침: 같은 문항, 남은 문제 수 그대로, 답 2개만 저장.
  - 제출 버튼 두 번 연속 → 답 1개만 저장.
  - 잠긴 단원 안내, 없는 단원 404.
  - 오답 다음 날 대시보드에 "개념 복습" → /review 문항.
  - 기존 어휘 e2e는 어휘를 마친 뒤 시작 버튼이 단원으로 가는 것으로 바꿨다.
- e2e가 찾은 버그: 마지막 평가 문항을 제출하면 결과 단계로 바뀌면서 해설이 사라졌다. 문항 화면을 문항 id로만 구분하게 고쳤다.
- lint, typecheck, validate:content, build 통과.

## 하지 않은 것

- 실제 단원 콘텐츠(UNIT 0-05): 단계 8 파이프라인으로 만든다. 그 전까지 운영 빌드에는 단원이 없어 대시보드에 단원 줄이 나오지 않는다.
- 학습 이벤트 서버 수집(analyzer_action, question_answer 등): 단계 9. 지금은 브라우저에만 남는다.
- 문제 오류 신고 버튼: 단계 8.
- 화살표·접기 모드: `SentenceAnalyzer`의 `mode` prop만 열어 두었다(13-4 P4).
