# English 90 — 학습 시스템 설계서 v2.0

Oct 31, 2026 · @Kmarx

## 1. 개요와 v2 핵심 변경

v2는 첫 개발 범위를 "어휘 복습 + 문장 구조 분석기 + 실사용 로그"로 좁히고, 콘텐츠 생산을 개발과 같은 급의 작업으로 올린다. 교육 철학(이해 → 연습 → 진단 → 재학습)과 콘텐츠·UI·엔진 분리 원칙은 v1을 그대로 유지한다.

| 영역 | v1 | v2 |
| --- | --- | --- |
| 첫 구현 범위 | LEVEL 0 문법 3개 단원 | 어휘 SRS + UNIT 0-05 1개 + 문장 분석기 |
| 커리큘럼 | 8단계, 문법 3단계(약 22\~28주) | 7단계, 고교 문법을 구문 독해에 흡수 |
| 어휘 | 병행 트랙, 목표량 없음 | 단계별 누적 목표량 + 매일 학습의 중심 축 |
| 문장 데이터 | 문항 스키마만 존재 | span 기반 문장 구조 주석을 핵심 자산으로 정의 |
| 오답 진단 | 추가 질문으로 원인 확인 | 오답 선택지마다 오개념 태그(작성 시점에 부여) |
| 복습 알고리즘 | 직접 설계한 간격 | FSRS(ts-fsrs) 사용 |
| 저장소 | P1\~P2 localStorage만 | P1부터 익명 학습 로그를 서버에 수집 |
| 콘텐츠 제작 | AI 생성은 P4 | 제작자용 생성·검수 파이프라인을 P1부터 운영 |
| 대상·수익 모델 | 정의 없음 | 타깃 학년·결제자를 명시하고 교사 배정 모델 검증 |
| 개발 지시(Claude Code) | 프롬프트 1개로 전체 구현 | 4개 프롬프트로 분할 |
| P1 성공 기준 | 기능이 작동한다 | 실제 학생이 2주간 계속 사용한다 |

## 2. 대상 학습자와 운영 모델

1차 타깃은 영어 기초가 부족한 중2\~고1로 가정한다. 전 과정 추정 기간(12\~15개월)이 수능까지 남은 시간 안에 들어오는 학년이기 때문이다. 고2 이상 노베이스는 2차 타깃으로 두고, 단축 경로(어휘 + 구문 + 듣기 우선)를 별도로 설계한다.

### 운영 모델 비교

| 모델 | 결제자 | 장점 | 약점 | 판단 |
| --- | --- | --- | --- | --- |
| 학생 개인 구독 | 학생·학부모 | 구조가 단순함 | 노베이스 학생의 자기주도 지속률이 낮음 | 2차 |
| 학부모 관리형 구독 | 학부모 | 결제 의사가 분명함 | 학부모가 학습을 직접 관리하기 어려움 | 보완 기능으로 |
| 교사 배정형(B2B2C) | 공부방·과외·소규모 학원 | 교사가 진도를 관리해 지속률 확보 | 교사용 화면 개발 필요 | 1차 검증 대상 |

검증 단계(P1\~P2)는 공부방 또는 과외 교사 1\~2명과 함께 진행한다. 교사가 학생에게 앱을 배정하고, 학습 기록을 보며 피드백하는 구조가 실제로 쓰이는지 확인한다.

### 동기 유지 장치

- 하루 목표 시간을 15·30·60분 중에서 학생이 고른다. 처음부터 90\~120분을 요구하지 않는다.
- 대시보드의 주 행동은 "오늘 학습 시작" 하나다. 복습 → 어휘 → 단원 순서는 엔진이 정한다.
- 연속 학습일(streak)은 보조 지표로만 쓰고, 끊겨도 벌점 없이 다시 시작하게 한다.
- 교사·보호자에게 주간 리포트(학습일수, 학습 시간, 막힌 개념)를 보낸다. P3부터 구현한다.

## 3. 재구성된 커리큘럼

커리큘럼은 7단계로 줄이고, 고교 문법은 독립 단계가 아니라 구문 독해 안에서 "해석에 필요한 문법"으로 가르친다. 수능 읽기 점수를 실제로 좌우하는 것은 어휘량, 긴 문장 처리, 지문 논리이므로 세 축에 시간을 더 배분한다. 듣기는 별도 모듈로 분리해 나중에 개발한다(3-4).

### 3-1. 단계 구조 (기간은 주 6일·하루 45\~60분 가정의 추정치)

| 단계 | 이름 | 기간(주) | 핵심 내용 | 졸업 과제 |
| --- | --- | --- | --- | --- |
| L0 | 영어의 시작 | 4\~6 | 발음 기초, 주어·동사, be동사·일반동사, 부정·의문 | 3\~5단어 문장의 주어·동사·목적어 표시 |
| L1 | 기초 문장 | 6\~8 | 품사, 문장 성분, 1\~5형식, 기본 시제, 전치사구 | 3\~5문장 글의 내용 파악 |
| L2 | 핵심 문법 | 8\~10 | 완료, 조동사, 수동태, 준동사, 접속사, 관계사 기초, 비교 | 두 절이 연결된 문장 해석 |
| L3 | 구문 독해 | 10\~12 | 긴 주어, 관계절 중첩, 분사구문, 도치·생략, 병렬, 가정법 | 고교 수준 복문에서 주절과 수식 분리 |
| L4 | 지문 독해 | 8\~10 | 주제·요지, 글 구조, 논리 관계, 지시어, 추론 | 150\~200단어 지문 요지 한 문장 요약 |
| L5 | 수능 유형 | 10\~12 | 읽기 유형별 전략, 어법·어휘 (14장 유형 지도 기준) | 유형별 제한 시간 내 정답률 기준 통과 |
| L6 | 실전 | 6\~8 | 45문항·70분 모의평가, 고난도, 시간 관리 | 새 모의평가 3회 연속 90점 이상 |

합계는 약 52\~66주(12\~15개월)이다. 진단 결과에 따라 이미 아는 단원은 건너뛰므로 학생마다 기간이 다르다.

### 3-2. 문법 축소 원칙

- 문법 용어는 해석에 필요한 최소한만 쓴다. "분사구문"이라는 이름보다 "쉼표 앞 -ing 덩어리가 주절을 설명한다"는 해석 방법을 먼저 가르친다.
- 어법 문항(수능 1문항) 대비는 L5에서 유형 학습으로 처리한다.
- 모든 문법 단원은 SentenceAnalyzer 연습으로 끝난다. 정의를 맞히는 문항만으로 단원을 통과할 수 없다.

### 3-3. 어휘 트랙 (매일, 모든 단계)

| 단계 종료 시점 | 누적 목표 어휘 | 출처 |
| --- | --- | --- |
| L0 | 400 | 중학 필수 어휘 중 고빈도 |
| L1 | 900 | 중학 필수 어휘 |
| L2 | 1,600 | 중학 필수 어휘 완료 + 고1 기초 |
| L3 | 2,600 | 고1 수준 어휘 |
| L4 | 3,600 | 고2\~고3 수능 빈출 |
| L5\~L6 | 4,500 이상 | 수능 빈출 + 지문 속 다의어 |

목표량은 앱 내부 기준(가정)이며, 실사용 데이터로 조정한다. 하루 신규 단어 수는 하루 목표 시간에 따라 10·15·20개로 정하고, FSRS가 복습량을 계산한다. 단어 카드는 뜻 확인 → 발음 → 예문 빈칸 → 문맥 의미 판별 순서로 난이도를 올린다.

### 3-4. 듣기 트랙 — 보류, 별도 모듈

| 구간 | 내용 | 스크립트 노출 |
| --- | --- | --- |
| L0\~L1 | 단어·짧은 문장 발음, 받아쓰기 | 항상 표시 |
| L2\~L3 | 2\~4턴 짧은 대화, 핵심 정보 찾기 | 듣기 후 선택 표시 |
| L4 | 수능형 대화·담화, 목적·의견·관계 | 1회 듣기 후 표시 |
| L5\~L6 | 17문항 실전 속도, 연속 풀이 | 채점 후에만 표시 |

듣기는 음성 제작·재생 기능과 함께 별도 모듈로 분리하고, 읽기 트랙(어휘·문법·구문·독해)을 먼저 완성한 뒤 개발한다. 위 표는 그때 적용할 계획으로 남겨 둔다. 다만 듣기는 37점이라 90점 목표에서 뺄 수 없으므로, 그 전까지는 학습자가 외부 자료로 듣기를 준비하도록 대시보드에 안내한다(14-1 실점 예산 참고).

## 4. 핵심 데이터 모델

프로젝트의 핵심 자산은 "구조 주석이 달린 문장"과 "오개념이 태깅된 문항"이다. 이 두 모델을 P1에서 확정하고, 이후 단계에서는 필드를 추가만 한다.

### 4-1. 문장 구조 주석 (AnnotatedSentence)

토큰 범위(span)로 역할을 표시하고, `parent`·`modifies`로 중첩과 수식 관계를 표현한다. L0의 주어·동사 찾기부터 L3의 관계절 중첩까지 같은 구조를 쓴다.

```json
{
  "id": "S-L3-0012",
  "level": "L3",
  "text": "The students who regularly review what they have learned are more likely to remember it.",
  "tokens": ["The","students","who","regularly","review","what","they","have","learned","are","more","likely","to","remember","it","."],
  "spans": [
    { "id": "subj", "role": "SUBJECT", "range": [0, 8] },
    { "id": "head", "role": "HEAD_NOUN", "range": [1, 1], "parent": "subj" },
    { "id": "rel", "role": "REL_CLAUSE", "range": [2, 8], "parent": "subj", "modifies": "head" },
    { "id": "ncl", "role": "NOUN_CLAUSE", "range": [5, 8], "parent": "rel", "function": "OBJECT" },
    { "id": "verb", "role": "MAIN_VERB", "range": [9, 9] },
    { "id": "comp", "role": "COMPLEMENT", "range": [10, 14] }
  ],
  "translation": "배운 것을 규칙적으로 복습하는 학생들은 그것을 기억할 가능성이 더 높다.",
  "chunkedTranslation": ["배운 것을 규칙적으로 복습하는", "학생들은", "그것을 기억할 가능성이 더 높다"],
  "skills": ["long_subject", "relative_clause", "noun_clause_what"],
  "reviewStatus": "approved"
}
```

역할 코드는 SUBJECT, MAIN\_VERB, OBJECT, COMPLEMENT, MODIFIER, HEAD\_NOUN, REL\_CLAUSE, NOUN\_CLAUSE, ADV\_CLAUSE, PARTICIPLE\_PHRASE, PREP\_PHRASE, INFINITIVE\_PHRASE로 시작하고 필요할 때 추가한다. 화면에는 색상과 함께 역할 이름·기호(S, V, O, C, M)를 항상 표시한다.

### 4-2. 문항 (Question)

오답 선택지마다 `misconception`을 붙인다. 학생이 고른 선택지만으로 오개념을 추정할 수 있어 추가 진단 문항이 줄어든다.

```json
{
  "id": "Q-L0-U05-001",
  "lessonId": "L0-U05",
  "type": "multiple_choice",
  "difficulty": 1,
  "sentenceId": "S-L0-0003",
  "prompt": "이 문장의 동사는 무엇인가요?",
  "options": [
    { "id": "A", "text": "The", "misconception": "article_as_word_class_confusion" },
    { "id": "B", "text": "boy", "misconception": "subject_as_verb" },
    { "id": "C", "text": "reads" },
    { "id": "D", "text": "book", "misconception": "object_as_verb" }
  ],
  "answer": "C",
  "skills": ["verb_identification"],
  "explanation": {
    "summary": "reads가 '읽는다'는 동작을 나타내는 동사입니다.",
    "byOption": {
      "B": "boy는 동작을 하는 사람, 즉 주어입니다.",
      "D": "book은 읽는 대상, 즉 목적어입니다."
    }
  },
  "variantGroup": "VG-verb-id-L0",
  "source": { "type": "original", "generatedBy": "ai_draft", "reviewedBy": "kmarx" },
  "reviewStatus": "approved",
  "version": 1
}
```

`variantGroup`은 같은 개념을 묻는 동형 문항 묶음이다. 복습 때는 같은 그룹에서 아직 풀지 않은 문항을 우선 낸다.

## 5. 학습 엔진

엔진은 세 가지를 결정한다: 오늘 무엇을 할지, 단원을 통과시킬지, 틀렸을 때 무엇을 다시 가르칠지. 모두 순수 함수 규칙으로 구현하고, AI는 이 결정에 관여하지 않는다.

### 5-1. 하루 흐름과 통과 판정

&#91;embedded content: 하루 학습 흐름과 단원 통과 판정 · 9단계, 판정 1개\]

복습이 항상 먼저 오고, 형성평가에서 떨어지면 같은 문항을 다시 풀지 않고 오개념 보충 후 같은 개념의 새 문항으로 재평가한다.

### 5-2. 숙달 기준 (v2)

| 판정 | 조건 | 처리 |
| --- | --- | --- |
| 숙달 | 신규 문항 8개 이상, 정답률 85% 이상, 분석기 과제 통과, 다른 날 지연 확인 1회 통과 | skill 복습 카드를 긴 간격으로 전환 |
| 진행 가능 | 위 조건 중 지연 확인만 남음 | 다음 단원 해금, 2\~3일 뒤 지연 확인 예약 |
| 보충 | 정답률 60\~84% | 가장 많이 나온 오개념의 보충 블록 + 동형 문항 4개 |
| 기초 재확인 | 정답률 60% 미만 | 선수 skill 진단 문항 3개 → 실패 시 선수 단원으로 복귀 |
| 혼동 | 같은 오개념 3회 이상 | 두 개념을 나란히 비교하는 대조 블록 제공 |

문항 수가 8개 미만이면 정답률을 판정에 쓰지 않는다. 숫자 기준은 파일럿 데이터로 보정한다.

### 5-3. 오답 진단

학생이 고른 오답 선택지의 `misconception`이 1차 진단이다. 같은 오개념이 2회 이상 나오면 `confirmed`, 1회면 `suspected`로 기록한다. 시간 초과로 틀린 경우는 TIM으로 따로 기록하고, 어휘 카드 기록에서 해당 지문의 핵심 단어를 모르는 상태였다면 VOC로 함께 표시한다. v1의 7개 원인 코드(VOC, GRM, SYN, LOG, INF, LIS, TIM)는 오개념의 상위 분류로 유지한다.

### 5-4. 복습 (FSRS)

어휘와 skill 모두 같은 ReviewCard로 관리하고 ts-fsrs가 다음 복습일을 계산한다. 어휘 카드는 학생의 자기 평가(다시·어려움·보통·쉬움)를, skill 카드는 문항 정오와 응답 시간을 평가 등급으로 변환해 넣는다. 하루 복습량이 목표 시간을 넘으면 신규 학습량을 자동으로 줄인다.

## 6. 콘텐츠 생산 파이프라인

전체 과정에 필요한 콘텐츠는 문항 4,000개 안팎이며, 사람이 직접 쓰면 개발보다 오래 걸린다. 그래서 AI가 초안을 만들고, 프로그램이 자동 검증하고, 사람은 검수만 하는 구조를 P1부터 운영한다. 학생에게 보이는 AI 튜터는 P4까지 미룬다.

### 6-1. 분량 추정

| 콘텐츠 | 추정 필요량 | 주 생산 방식 |
| --- | --- | --- |
| 단원(LessonBlock 묶음) | 약 90개 | AI 초안 + 직접 집필·수정 |
| 문항 | 3,000\~5,000개 | AI 생성 + 자동 검증 + 검수 |
| 구조 주석 문장 | 2,000개 이상 | AI 주석 + 검수 |
| 어휘 카드 | 4,500개 이상 | 기존 어휘 목록 + AI 예문 + 검수 |
| 듣기 문항 | 500개 이상 | 보류 (듣기 모듈 개발 시) |
| 실전 모의평가 | 6회분 이상(졸업 판정 3회 + 연습) | 직접 설계 + AI 보조 |

검수 속도를 하루 50문항으로 가정하면 문항 4,000개 검수에 약 80일이 든다. 이 수치가 전체 일정의 실제 상한이므로, 단계별 출시는 콘텐츠 검수 진도에 맞춘다.

### 6-2. 생성 → 검수 흐름

1. 명세 작성: 단원·skill·오개념 목록과 난이도, 사용 가능한 어휘 범위를 JSON으로 정한다.
2. AI 생성: `scripts/content-pipeline/`의 배치 스크립트가 Claude API로 문항·주석 초안을 만든다. 출력은 4장의 스키마 JSON으로 강제한다.
3. 자동 검증: Zod 스키마, 정답 유일성, span 범위 유효성, 어휘 범위 초과 여부, 오답 선택지의 오개념 태그 누락을 검사한다.
4. 교차 풀이: 정답을 가린 문항을 별도 모델 호출(ANTHROPIC_CROSSCHECK_MODEL, 미지정 시 생성과 같은 모델)로 다시 풀게 해서 정답이 다르면 "의심"으로 표시한다.
5. 사람 검수: 관리자 검수 화면에서 승인·수정·폐기를 고른다. 의심 표시 문항을 먼저 본다.
6. 투입: 승인된 항목만 `content/` 에 병합되고, 빌드 시 다시 스키마 검증을 통과해야 한다.

### 6-3. 검수 상태

| 상태 | 의미 | 학생 노출 |
| --- | --- | --- |
| draft | AI 초안 | 아니요 |
| auto\_checked | 자동 검증 통과 | 아니요 |
| flagged | 교차 풀이 불일치 또는 규칙 위반 | 아니요 |
| approved | 사람 검수 완료 | 예 |
| retired | 오류 발견·교체로 폐기(기록은 유지) | 아니요 |

학생 응답에서 정답률이 비정상적으로 낮거나 "문제 오류 신고"가 들어온 문항은 자동으로 flagged로 되돌린다.

기간은 1인 개발과 콘텐츠 검수 속도를 기준으로 한 추정치이며, 전체 약 14\~18개월다. P4·P5의 관문 수치는 P2 파일럿 데이터를 본 뒤 확정한다.

## 9. P1 상세 사양

P1의 성공 기준은 "기능이 작동한다"가 아니라 "실제 학생 3\~5명이 2주 동안 매일 쓰고, 어디서 막히는지 로그로 보인다"이다. 이미 확보한 중학 필수 어휘 목록을 어휘 SRS의 첫 콘텐츠로 쓴다.

### 9-1. 범위

| 포함 | 제외(이후 단계) |
| --- | --- |
| 어휘 SRS: 중학 필수 어휘 중 고빈도 400개, 카드 4종 | 로그인·계정 |
| UNIT 0-05 "주어와 동사" 1개 단원 (개념 → 분석 → 연습 → 평가) | 교사·보호자 화면 |
| SentenceAnalyzer (탭 방식, S·V·O 3역할) | 듣기 |
| PracticeQuestion: 객관식, 참·거짓 + 오개념별 해설 | 학생용 AI 튜터 |
| 오늘의 학습 대시보드 (복습 → 어휘 → 단원 자동 배치) | 모의평가 |
| localStorage 진도 + 익명 이벤트 서버 수집 | 관리자 콘텐츠 편집기(검수 화면만 포함) |
| 콘텐츠 검수 화면(승인·수정·폐기) | 결제 |

### 9-2. 화면

1. 시작: 이름 대신 닉네임, 하루 목표 시간(15·30·60분) 선택, 익명 ID 발급.
2. 대시보드: "오늘 학습 시작" 버튼 1개와 오늘 할 일 목록(예상 시간 포함).
3. 어휘 복습: 카드 → 응답 → FSRS 평가(다시·어려움·보통·쉬움) → 다음 카드.
4. 단원 학습: LessonBlock 순서대로 진행, 중간 이탈 후 이어하기.
5. 문항·피드백: 제출 전 정답 비노출, 제출 후 선택한 선택지 기준 해설.
6. 완료 화면: 오늘 학습량, 다음 복습 예정 수.

### 9-3. 수집 이벤트

| 이벤트 | 주요 데이터 | 확인할 질문 |
| --- | --- | --- |
| session\_start / session\_end | 시간, 목표 시간 | 매일 들어오는가, 얼마나 머무는가 |
| card\_review | 단어 id, 평가, 응답 시간 | 어떤 단어가 계속 틀리는가 |
| block\_view | 단원 블록 id, 체류 시간 | 어느 설명에서 이탈하는가 |
| question\_answer | 문항 id, 선택지, 정오, 시간 | 어떤 오개념이 많은가 |
| analyzer\_action | 문장 id, 선택한 span과 역할 | 주어·동사 구분 중 어디서 막히는가 |
| report\_error | 문항 id, 신고 내용 | 콘텐츠 오류가 있는가 |

### 9-4. 성공 지표 (2주 파일럿)

| 지표 | 목표 |
| --- | --- |
| 14일 중 학습일수 | 학생의 60% 이상이 10일 이상 |
| 하루 평균 학습 시간 | 선택한 목표 시간의 70% 이상 |
| UNIT 0-05 평가 통과 | 참여 학생의 80% 이상 |
| 7일 후 지연 평가 정답률 | 단원 평가 정답률 대비 하락 10%p 이내 |
| 어휘 복습 정답률 | 70\~90% 구간 유지(너무 쉽거나 어렵지 않음) |
| 콘텐츠 오류 신고 | 확인된 오류 0건으로 수렴 |

목표치는 첫 가설이며, 파일럿 결과로 P2 설계를 조정한다.

## 10. Claude Code 개발 방식과 분할 프롬프트

Claude Code에는 한 세션에 하나의 프롬프트만 주고, 각 단계의 테스트가 통과한 뒤 다음으로 넘어간다. 교육 콘텐츠는 Codex가 작성하지 않으며, 6장의 파이프라인과 사람 검수를 거쳐 들어온다. 모든 프롬프트 앞에 이 설계서 파일(`docs/DESIGN_v2.md`)을 함께 두고 시작한다.

듣기 보류와 기출 분석(14장)을 반영한 최신 단계별 프롬프트는 Claude Code 프롬프트 탭에 있다. 아래 프롬프트 1\~4는 그 이전 초안이다.

### 10-0. Claude Code 프로젝트 세팅

프로젝트 규칙은 `CLAUDE.md`에, 반복 점검은 서브에이전트와 훅에 맡긴다. 프롬프트마다 같은 규칙을 다시 쓸 필요가 없어지고, 콘텐츠 검증이 자동으로 돌아간다.

```
english90/
├── CLAUDE.md                      프로젝트 규칙(매 세션 자동 로드)
├── docs/DESIGN_v2.md              이 설계서(Markdown으로 내보내 저장)
└── .claude/
    ├── settings.json              훅 설정
    └── agents/
        └── content-reviewer.md    콘텐츠 1차 검수 서브에이전트
```

**CLAUDE.md**

```markdown
# English 90

설계 기준: docs/DESIGN_v2.md. 설계와 다른 구현이 필요하면 먼저 제안하고 승인을 받는다.

## 명령
- npm run dev / lint / typecheck / test / validate:content / build

## 규칙
- 스키마의 단일 원천은 lib/schema (Zod). 타입은 z.infer로만 만든다.
- lib/engine 은 순수 함수만. 브라우저·DB에 의존하지 않는다.
- content/ 의 문항·정답·해설·예문을 새로 작성하거나 수정하지 않는다. 콘텐츠는 파이프라인과 사람 검수로만 들어온다.
- 제출 전에는 정답·해설을 DOM에 렌더링하지 않는다.
- 작동하지 않는 기능을 완성된 것처럼 표시하지 않는다.
- UI 문구는 한국어, 코드·커밋 메시지는 영어.

## 완료 기준
- lint, typecheck, test, validate:content, build 가 모두 통과한 뒤 구현·미구현·테스트 결과를 보고한다.
```

**.claude/agents/content-reviewer.md**

```markdown
---
name: content-reviewer
description: content/ 또는 draft 콘텐츠의 정답·해설·문장 주석 오류를 점검할 때 사용
tools: Read, Grep, Glob
---
너는 중고등 영어 교육 콘텐츠 검수자다. 각 항목에 대해 다음을 확인하고 표로 보고한다.
- 정답이 하나뿐이고 해설과 일치하는가
- 오답 선택지의 misconception 태그가 실제 오답 이유와 맞는가
- 문장 주석의 역할(S·V·O·절)이 문법적으로 맞는가
- 한국어 해석이 자연스럽고 정확한가
- 해당 단계의 어휘 범위를 넘는 단어가 있는가
파일은 수정하지 말고 문제 항목 id와 이유만 보고한다.
```

**.claude/settings.json (훅)** — 파일을 수정할 때마다 콘텐츠 검증을 돌린다.

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          { "type": "command", "command": "npm run validate:content --silent" }
        ]
      }
    ]
  }
}
```

훅 설정 형식은 버전에 따라 바뀔 수 있으므로, 적용 후 Claude Code 안에서 `/hooks`로 등록 상태를 확인한다. validate:content 스크립트는 프롬프트 1에서 만들어지므로 훅은 프롬프트 1 완료 후에 켠다.

### 10-1. 작업 흐름

1. 빈 폴더에서 `claude`를 실행하고, 이 설계서를 Markdown으로 내보내 `docs/DESIGN_v2.md`로 저장한다. 위의 `CLAUDE.md`도 함께 둔다.
2. 각 프롬프트는 계획 모드(Plan mode)에서 먼저 실행해 구현 계획만 받는다. 계획이 설계서와 맞는지 확인한 뒤 실행을 승인한다.
3. 프롬프트 하나가 끝나면 완료 기준 통과를 확인하고 커밋한 뒤 `/clear`로 대화를 비우고 다음 프롬프트로 넘어간다.
4. AI가 만든 콘텐츠 초안은 `content-reviewer` 서브에이전트로 1차 점검하고, 최종 승인은 직접 한다.

### 프롬프트 1 — 스키마·타입·검증

```markdown
# 작업: English 90 데이터 기반 구축

docs/DESIGN_v2.md의 4장(핵심 데이터 모델)을 읽고 다음을 구현하라.

1. Next.js + TypeScript + Tailwind 프로젝트를 초기화한다. 버전은 현재 안정 버전으로 고정한다.
2. lib/schema/ 에 Zod 스키마를 만든다: Skill, Misconception, AnnotatedSentence, Question, Vocabulary, LessonBlock, Unit, ReviewCard, Attempt, LearningEvent.
3. TypeScript 타입은 Zod에서 z.infer로만 만든다(별도 타입 정의 금지).
4. scripts/validate-content.ts 를 만든다. content/ 아래 모든 JSON을 검사한다:
   - 스키마 유효성
   - Question.answer가 options에 존재하고 정답이 하나뿐인지
   - 정답이 아닌 모든 선택지에 misconception이 있는지, 그 id가 misconceptions.json에 있는지
   - AnnotatedSentence의 span range가 tokens 범위 안인지, parent·modifies가 존재하는 span을 가리키는지
   - reviewStatus가 approved가 아닌 항목이 학생용 빌드에 포함되지 않는지
5. 위 규칙마다 통과·실패 사례를 가진 Vitest 테스트를 작성한다.
6. package.json에 validate:content를 추가하고 build 전에 실행되게 한다.

화면은 만들지 않는다. 끝나면 lint, typecheck, test, build 결과를 보고하라.
```

## 11. 검증 계획과 개인정보

교육 효과는 "이해 → 전이 → 유지 → 지속" 네 가지로 나누어 측정하고, P1 파일럿은 익명 데이터만 수집해 미성년자 개인정보 부담을 최소화한다.

### 11-1. 검증 항목

| 항목 | 측정 방법 | 데이터 출처 |
| --- | --- | --- |
| 개념 이해 | 단원 평가 정답률, 오개념별 오답 분포 | question\_answer |
| 지식 전이 | 연습에 없던 새 문장 분석 정답률 | analyzer\_action (전이용 문장 세트) |
| 기억 유지 | 7일 뒤 지연 평가 정답률 | question\_answer + 복습 일정 |
| 학습 지속 | 14일 중 학습일수, 세션 길이 | session\_start / session\_end |
| 설명 품질 | 블록별 체류 시간·이탈 지점, 학생·교사 인터뷰 | block\_view + 인터뷰 |

파일럿이 끝나면 블록별 이탈률이 높은 설명, 오답이 몰린 오개념, 너무 쉽거나 어려운 단어를 목록으로 뽑아 P2 콘텐츠 수정 우선순위로 쓴다.

### 11-2. 개인정보 원칙

- P1: 이름·연락처·학교를 받지 않는다. 닉네임과 기기별 익명 ID만 쓴다. 학생 식별은 파일럿 담당 교사가 오프라인으로만 한다.
- P2 이후 계정 도입 시: 개인정보 처리방침, 보존 기간, 탈퇴 시 삭제 기능, 학습 기록 열람 권한(학생·보호자·배정 교사)을 함께 설계한다.
- 만 14세 미만 학생의 개인정보를 수집하려면 법정대리인 동의가 필요하다(개인정보 보호법). 중2 이하가 포함될 수 있으므로 계정 도입 전에 동의 절차를 확정한다.
- 교사 배정 모델에서는 교사가 볼 수 있는 데이터 범위를 학습 기록으로 한정하고, Supabase RLS로 강제한다.

법적 요건은 계정 도입 시점에 전문가 검토를 받는다.

## 13. 인터랙션 설계

모든 학습 행동은 "읽고 보기"가 아니라 "직접 조작하기"로 설계한다. 학생이 문장을 태깅하고, 접고, 끊고, 조립하는 모든 조작이 즉시 피드백을 받고, 동시에 진단 데이터로 남는다.

### 13-1. 원칙

- **먼저 해보고, 나중에 설명한다.** 새 개념은 짧은 예측 과제로 시작하고, 학생의 선택을 본 뒤 설명을 연다.
- **맞다·틀리다보다 이유를 보여준다.** 오답은 선택한 오개념에 맞는 메시지와 시각적 표시(어느 부분이 어긋났는지)로 돌려준다.
- **구조가 움직여야 이해된다.** 애니메이션은 장식이 아니라 문장 구조 변화(수식어가 붙고, 절이 접히고, 화살표가 이어짐)를 보여줄 때만 쓴다.
- **탭과 키보드가 기본이다.** 모든 과제는 드래그 없이 탭만으로 끝낼 수 있고, 드래그는 데스크톱의 선택 사항이다.
- **조작은 모두 기록한다.** 어떤 토큰을 어떤 역할로 골랐는지까지 이벤트로 남겨 5장의 진단과 9-3의 로그에 쓴다.

### 13-2. 인터랙션 카탈로그

| 인터랙션 | 학생 행동 | 가르치는 것 | 단계 | 구현 |
| --- | --- | --- | --- | --- |
| 역할 태깅 | 단어를 탭하고 S·V·O·C·M 중 하나를 지정 | 문장 성분 | L0\~L1 | SentenceAnalyzer |
| 문장 조립 | 단어 칩을 순서대로 탭해 문장 완성 | 영어 어순 | L0\~L2 | SentenceBuilder |
| 문장 확장 사다리 | 핵심 문장에 수식어 블록을 하나씩 붙여 문장을 키움 | 수식 구조 | L1\~L3 | SentenceBuilder 확장 모드 |
| 형태 토글 | 시제·능동/수동·긍정/부정 스위치를 바꾸면 문장이 바뀜 | 형태 변화와 의미 | L1\~L2 | FormToggle |
| 끊어 읽기 | 의미 단위 경계를 탭해 / 를 넣고, 끊을 때마다 구간 해석 표시 | 청크 해석 | L2\~L4 | ChunkReader |
| 수식 화살표 | 수식어를 탭한 뒤 꾸밈을 받는 단어를 탭해 화살표 연결 | 수식 범위 | L3 | SentenceAnalyzer 화살표 모드 |
| 구조 접기 | 수식어·절을 접어 뼈대 문장만 남기고 다시 펼침 | 긴 문장의 주절 찾기 | L3\~L4 | SentenceAnalyzer 접기 모드 |
| 근거 하이라이트 | 정답을 고르기 전에 근거 문장을 지문에서 탭 | 추론 근거 | L4\~L5 | ReadingPassage |
| 문단 카드 정렬 | (A)(B)(C) 카드를 순서대로 배치, 지시어·연결어 단서 켜기 | 글의 순서 | L4\~L5 | ParagraphSorter |
| 예측 후 공개 | 빈칸의 의미 방향을 먼저 고른 뒤 선택지 공개 | 빈칸 추론 | L5 | PracticeQuestion 2단계 모드 |
| 단어 카드 4단 | 뜻 → 발음 → 예문 빈칸 → 문맥 의미 판별 | 어휘 | 전 단계 | VocabularyCard |
| 구간 반복 듣기 (보류) | 문장 단위 반복, 0.75\~1.0배속, 받아쓰기 | 듣기 | 전 단계 | ListeningPlayer |
| 실전 타이머 | 남은 시간, 문항 표시 후 나중에 보기, 종료 후 일괄 채점 | 시간 관리 | L6 | ExamShell |

### 13-3. 피드백과 힌트

힌트는 3단계로 연다. 1단계는 방향("동작을 나타내는 단어를 찾아보세요"), 2단계는 범위(후보 구간 강조), 3단계는 정답과 근거다. 사용한 힌트 단계는 숙달도 계산에 반영해, 3단계 힌트로 맞힌 문항은 정답으로 세지 않는다.

틀린 조작은 해당 부분만 흔들림과 색으로 표시하고, 오개념 메시지를 바로 옆에 띄운다. 맞힌 조작은 역할 기호와 해석 조각이 제자리에 고정되며 다음 단계로 자연스럽게 넘어간다.

### 13-4. 단계별 도입 계획

| 단계 | 넣을 인터랙션 |
| --- | --- |
| P1 | 역할 태깅(S·V·O), 문장 조립, 단어 카드 4단, 3단계 힌트 |
| P2 | 문장 확장 사다리, 형태 토글, 기초 진단용 빠른 태깅 |
| P3 | 끊어 읽기 |
| P4 | 수식 화살표, 구조 접기, 근거 하이라이트 |
| P5 | 문단 카드 정렬, 예측 후 공개, 실전 타이머 |

### 13-5. 데이터 모델 추가 사항

- AnnotatedSentence에 `chunks`(끊어 읽기 경계 토큰 위치)와 `expansionSteps`(문장 확장 사다리의 단계별 블록)를 추가한다.
- Passage 모델에 `evidenceSpans`(문항별 정답 근거 문장 범위)를 추가한다.
- LearningEvent에 `interaction`(조작 종류)과 `hintLevel`을 추가한다.

## 14. 기출 분석 기반 90점 설계 (읽기 트랙)

읽기 트랙의 모든 콘텐츠는 공개된 평가원 기출을 분석해 얻은 "출제 사양"에 맞춰 자체 제작한다. 기출 원문은 분석에만 쓰고 앱에는 넣지 않으며, 앱에는 분석 결과(통계·태그·블루프린트)만 반영한다.

### 14-1. 점수 구조와 실점 예산

수능 영어는 듣기 17문항 37점, 읽기 28문항 63점이다 ([내일교육](https://www.localnaeil.com/News/View/648888)). 2028학년도에도 듣기 17문항을 포함한 45문항·70분 구성이 유지된다 ([내일교육 자료](https://file.naeiledu.co.kr/uploadfile/20250204/121304_070_071위클리포커스_ok_m.pdf)). 90점 이상이 1등급이므로 잃을 수 있는 점수는 10점, 문항으로는 3\~4개다.

| 영역 | 허용 실점(목표) | 담당 |
| --- | --- | --- |
| 듣기 17문항 | 0\~1문항 | 외부 자료 → 이후 듣기 모듈 |
| 읽기 A군(기본 유형) | 0\~1문항 | L4\~L5 |
| 읽기 B·C군(중·고난도) | 최대 2문항 | L3\~L6 |

듣기를 앱에서 다루지 않는 동안에도 실전 모의평가 졸업 기준(3회 연속 90점)은 듣기를 포함한 점수로 판정한다. 학습자에게는 이 점을 처음부터 안내한다.

### 14-2. 읽기 유형 지도

번호 배치는 최근 시험 기준이며, 분석 단계에서 연도별로 확인해 갱신한다. 최근 모의평가에서도 빈칸 추론(33·34번)과 글의 순서(36·37번)가 변별 문항으로 꼽혔다 ([아시아투데이](https://www.asiatoday.co.kr/kn/view.php?key=20260604010001549)).

| 번호 | 유형 | 난도군 | 핵심 능력 | 담당 단계 |
| --- | --- | --- | --- | --- |
| 18 | 글의 목적 | A | 필자 의도 파악 | L4 |
| 19 | 심경·분위기 | A | 감정 어휘, 변화 지점 | L4 |
| 20 | 필자의 주장 | A | 주장 문장 찾기 | L4 |

| 22 | 요지 | A | 중심 문장 | L4 |
| 23 | 주제 | B | 중심 내용의 영어 표현 선택 | L4\~L5 |
| 24 | 제목 | B | 의미 압축, 비유적 제목 해석 | L5 |
| 25 | 도표 | A | 수치 비교 표현 | L4 |
| 26 | 내용 일치(인물) | A | 세부 정보 대조 | L4 |
| 27\~28 | 안내문 | A | 세부 정보 대조 | L4 |

### 14-3. 기출 분석 파이프라인

1. 수집: 평가원 홈페이지에 공개된 2018학년도(영어 절대평가 도입) 이후 수능과 6·9월 모의평가 문제지·정답을 내려받아 로컬 비공개 폴더 `corpus/`에 둔다. 이 폴더는 git과 배포 대상에서 제외한다.
2. 구조화: Claude Code 스크립트로 시험·번호·유형·배점·정답·지문·선택지를 JSON으로 추출한다.
3. 태깅: 문항마다 정답 근거 위치, 오답 선택지의 함정 유형, 핵심 구문 요소, 소재 분야를 붙인다. AI가 1차 태깅하고 직접 검수한다.
4. 통계: 어휘 빈도, 어법 포인트 빈도, 문장 길이·절 깊이 분포, 빈칸 위치 분포, 순서·삽입 단서 분포를 계산한다.
5. 블루프린트화: 유형별 출제 사양과 오답 함정 태그 체계를 문서와 JSON으로 만든다.
6. 반영: 블루프린트가 6장 생성 파이프라인의 입력이 되어 자체 지문·문항을 만든다.

| 분석 산출물 | 내용 | 앱 반영 위치 |
| --- | --- | --- |
| 수능 어휘 빈도표 | lemma별 출현 횟수, 출현 시험 수, 다의어 여부 | 3-3 어휘 트랙 순서, 14-5 커버리지 지표 |
| 어법 포인트 빈도표 | 29번 문항의 문법 포인트별 출제 횟수 | L3 구문·L5 어법 단원 우선순위 |
| 구문 복잡도 분포 | 문장 길이, 절 중첩 깊이, 수식 패턴 | L3 구문 단원 난이도 곡선 |
| 유형별 출제 사양 | 지문 길이, 정답 근거 위치, 선택지 구성 | 14-4 블루프린트 |

### 14-4. 유형별 블루프린트

자체 문항은 기출 문장을 옮기지 않고, 분석으로 얻은 사양만 따른다. 빈칸 추론 블루프린트의 구조는 다음과 같다(수치는 분석 결과로 채운다).

```json
{
  "type": "blank_inference",
  "items": "31-34",
  "passage": {
    "wordCount": "<기출 분포의 중앙 범위>",
    "avgSentenceLength": "<기출 평균>",
    "maxClauseDepth": "<기출 분포>",
    "vocabBand": "수능 어휘 빈도표 상위 N",
    "topicDomains": "<소재 분포 비율>"
  },
  "blank": {
    "positionDistribution": ["주제문", "결론부", "중간 재진술"],
    "answerBasis": "글의 핵심 주장을 다른 표현으로 바꿔 쓴 것",
    "evidenceSpans": "정답 근거 문장 최소 2곳"
  },
  "distractors": {
    "count": 4,
    "traps": ["opposite_claim", "partial_detail", "over_generalization", "keyword_reuse", "no_textual_basis"]
  },
  "requiredSkills": ["main_idea", "restatement_recognition", "contrast_signal"]
}
```

오답 함정 태그 초안: 반대 진술(opposite\_claim), 부분 일치(partial\_detail), 과잉 일반화(over\_generalization), 지문 단어 재사용(keyword\_reuse), 지문 근거 없음(no\_textual\_basis), 범위 이탈(scope\_shift). 기출 분석 후 확정하며, 학생이 같은 함정에 반복해서 걸리면 5-2의 "혼동" 처리로 대조 블록을 연다.

### 14-5. 어휘 설계: 수능 지문 커버리지

어휘 목표를 "몇 개 외웠는가"가 아니라 "기출 지문의 단어를 얼마나 아는가"로 잡는다. 학생이 숙달한 단어가 기출 지문 전체 단어에서 차지하는 비율을 "수능 지문 어휘 커버리지"로 계산해 대시보드에 보여준다.

- 목표: 커버리지 95% 이상, 최종 98%에 근접. 독해 연구에서 지문 이해의 기준으로 흔히 쓰는 범위를 출발점으로 삼고, 파일럿 데이터로 조정한다.
- 학습 순서: 기출 빈도표 상위부터. 3-3의 단계별 누적 목표량은 커버리지 목표에 맞춰 다시 계산한다.
- 30번(문맥상 어휘)과 다의어 대비: 빈도표에서 다의어로 표시된 단어는 "문맥 의미 판별" 카드를 추가로 만든다.
- 연어·구동사: 기출에서 자주 함께 쓰인 표현은 단어가 아니라 덩어리로 카드화한다.

### 14-6. 문법 설계: 해석 문법과 어법 문법

문법은 두 갈래로 나눈다. "해석 문법"은 L1\~L3에서 문장을 읽기 위해 배우고, "어법 문법"은 L5에서 29번 문항을 풀기 위해 기출 빈도 순으로 집중 훈련한다.

분석 전 가설 목록(기출 분석으로 순위 확정): 주어·동사 수 일치, 동사와 준동사 구별, 관계사(what·that·which, 관계부사), 능동·수동, 대명사·재귀대명사, 형용사·부사, 병렬 구조, 대동사, 도치. 각 포인트는 SentenceAnalyzer 구조 판단 문항과 어법 선택 문항을 한 묶음으로 만든다.

### 14-7. 기출 원문 취급 원칙

- 기출 원문은 `corpus/`에서 분석에만 쓰고, 저장소·앱·학생 화면에 넣지 않는다.
- 앱에는 통계, 태그, 블루프린트, 자체 제작 문항만 들어간다.
- 자체 지문은 기출 문장을 옮기거나 거의 그대로 바꿔 쓰지 않는다. 생성 파이프라인에 기출 코퍼스와의 n-gram 유사도 검사를 넣어 기준을 넘으면 flagged 처리한다. 유사도 검사기는 corpus/를 읽되 점수와 겹침 여부만 출력하고 원문을 출력하지 않는다.
